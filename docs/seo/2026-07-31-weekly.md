— the one post stuck at "Discovered, currently not indexed" last run — is
now "Submitted and indexed" (last crawled 28 Jul, mobile). No action was
needed beyond time; the IndexNow push from the last run doesn't reach
Google, so this was Google's own crawl catching up.

The site remains at the same funnel stage as last week: **indexed, real
impressions exist, but essentially zero clicks and thin query volume.**
GSC returned 3 total query rows this window (up from 2): `ato chatbot`
(pos 10, repeat), `ai tax australia` (pos 87, new — effectively invisible

a pattern — three rows total is not enough to act on beyond watching.

**Bing is the one number that's stopped looking like "still early" and
started looking like it might be stuck.** Zero crawled pages, zero in
index, and the homepage itself has never been crawled
(`LastCrawledDate: null`) — six days after site verification, well past
the ~48h Bing quotes for a new property. Nothing actionable changed here
this run (the IndexNow key is already live and was already pushed for the
one lagging URL last week), but if next run still shows zero movement,
that's worth a support inquiry with Bing rather than more waiting.

Per the skill's own calibration note: a flat week on traffic numbers this
small is not a failure by itself, but this is the **second consecutive run
with essentially no query growth** (2 → 3 rows) and **no new content
shipped**. The constraint is not technical — audit is clean, indexing is
resolved — it's volume: 6 posts is not yet enough surface area to generate
meaningful impressions, and no new post has published since before the
28 Jul run.

Not filing this as an issue — it's a lint-command ergonomics issue, not an
SEO or product one, and trivial to work around — but noting it so it
doesn't get mistaken for a real regression next time someone runs the
bare command.
